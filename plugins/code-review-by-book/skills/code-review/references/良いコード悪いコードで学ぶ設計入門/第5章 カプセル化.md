## OK privateコンストラクタ+ファクトリメソッドで目的別初期化

生成ロジックが多い場合はファクトリクラスを用意すること

```java
class GiftPoint {
  private static final int MIN_POINT = 0;
  private static final int STANDARD_MEMBERSHIP_POINT = 3000;
  private static final int PREMIUM_MEMBERSHIP_POINT = 10000;
  final int value;

  // コンストラクタはprivateにする
  private GiftPoint(final int point) {
    if (point < MIN_POINT) {
      throw new IllegalArgumentException("ポイントが0以上ではありません。");
    }

    value = point;
  }

  // staticなファクトリメソッドを目的別に用意
  static GiftPoint forStandardMembership() {
    return new GiftPoint(STANDARD_MEMBERSHIP_POINT);
  }

  static GiftPoint forPremiumMembership() {
    return new GiftPoint(PREMIUM_MEMBERSHIP_POINT);
  }
}
```

## OK フィールド、引数、ローカル変数は不変にすること

扱うデータをコンストラクタで初期化し、そのデータを操作するメソッドを定義

```java
class Location {
  final int x;
  final int y;

  Location(final int x, final int y) {
    this.x = x;
    this.y = y;
  }

  Location shift(final int shiftX, final int shiftY) {
    final int nextX = x + shiftX;
    final int nextY = y + shiftY;
    return new Location(nextX, nextY);
  }
}
```

## NG 多すぎる引数

ロジックがそれだけ複雑な可能性が高いので、別クラスへの分割を検討する

```java
int recoverMagicPoint(int currentMagicPoint, int originalMaxMagicPoint, List<Integer> maxMagicPointIncrements, int recoveryAmount) {
  int currentMaxMagicPoint = originalMaxMagicPoint;
  for (int each : maxMagicPointIncrements) {
    currentMaxMagicPoint += each;
  }

  return Math.min(currentMagicPoint + recoveryAmount, currentMaxMagicPoint);
}
```

## OK Tell, Don't Ask. (デメテルの法則)

ロジックを呼ぶ側(Party)ではなく、呼ばれる側(Equipments)に定義

```java
class Equipments {
  private boolean canChange;
  private Equipment head;
  private Equipment armor;
  private Equipment arm;

  void equipArmor(final Equipment newArmor) {
    if (canChange) {
      armor = newArmor;
    }
  }

  void deactivateAll() {
    head = Equipment.EMPTY;
    armor = Equipment.EMPTY;
    arm = Equipment.EMPTY;
  }
}
```
