# 要件

## 目的

ローカルPCに保存されたドキュメントを、外部への送信なしに横断検索できるようにする

Claude Codeから個人のドキュメントを探す手段はGrep/Globによる逐次探索しかなく、以下の課題がある

- 意味的に近い文書を見つけられない
- PDFやWord文書はテキストとして読めない
- 検索のたびに全ファイルを走査するため遅い

## 対象ユーザ

プログラマーではなく一般利用者

このため以下を前提とする

- 専門用語を避けた応答
- ファイルパスの羅列ではなく、ファイル名と内容の説明
- 検索対象がソースコードではなくドキュメント

## 機能要件

| 機能 | 内容 |
|---|---|
| 全文検索 | キーワードの完全一致による検索 |
| RAG検索 | 意味的な類似による検索 |
| ハイブリッド検索 | 上記2つを統合した検索 |
| 検索対象の管理 | フォルダの登録、削除、一覧 |
| インデックス管理 | 作成、進捗確認、中止 |

## 非機能要件

| 項目 | 要件 |
|---|---|
| ローカル完結 | 検索対象の内容を外部APIへ送信しない |
| 応答性 | インデックス作成中も他の操作をブロックしない |
| 差分更新 | 変更のないファイルを再処理しない |
| 縮退運転 | 埋め込みモデルが利用できなくても全文検索は動作する |

## 対象ファイル形式

v1で対応する形式

| 拡張子 | 扱い |
|---|---|
| `.md` `.markdown` `.txt` `.text` `.rst` | 平文として直接読み取り、エンコーディングは自動判定 |
| `.pdf` `.docx` `.pptx` | MarkItDownでMarkdownへ変換し、サイドカーとして保存 |

## スコープ外

| 対象 | 理由 |
|---|---|
| `.xlsx` `.rtf` | セル単位の行番号対応など個別の検討が必要、第2フェーズで対応 |
| `.doc` `.xls` `.odt` | OLEバイナリや外部プロセスへの依存が必要 |
| ソースコード、設定ファイル | 一般利用者向けのため対象外、チャンク分割の方針も異なる |
| 画像内テキストのOCR | ローカル完結の前提でモデルサイズが大きくなりすぎる |
| 検索結果の本文返却 | two-phase retrievalを採用、[03-architecture.md](03-architecture.md)を参照 |
