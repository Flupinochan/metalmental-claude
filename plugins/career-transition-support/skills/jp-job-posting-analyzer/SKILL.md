# 求人票分析と職務経歴書の調整

求人票を分析してマッチ度とギャップを特定し、jp-resume-writerで作成した職務経歴書を
応募先ごとにカスタマイズするためのskill

## 前提

日本の中途採用は転職エージェント経由の応募が多く、エージェントが求人票の解釈や
応募先への推薦文を補足する場面がある
そのため分析結果には、エージェントへの補足説明に使える要点も含める

## 分析手順

### ステップ1 求人票からの要件抽出

求人票を次の3分類に整理する

- 必須要件 (これがないと選考に進めない条件)
- 歓迎要件 (あると評価される条件)
- 求める人物像 (チームカルチャー、働き方への適性)

### ステップ2 マッチ度算出

次の式でマッチ度を算出する

```
マッチ度 = 必須要件の充足率 × 70% + 歓迎要件の充足率 × 30%
```

充足率は次の按分ルールで算出する

- 満たしている要件 1件につき1点、満たしていない要件は0点
- 経験年数や規模など部分的にしか満たさない要件は、実績÷求人票の要求値で按分する
  (例 「3年以上」の必須要件に対し2年の経験なら0.67点として計算する、上限は1点)
- 充足率 = 獲得点の合計 ÷ 要件総数 × 100

目安

- 90〜100% 経験が求人要件を上回っている、応募価値が高い
- 70〜89% 良好なマッチ、応募を推奨
- 50〜69% 一部ギャップあり、対策次第で応募可能
- 50%未満 ミスマッチの可能性が高い、応募前に要検討

### ステップ3 ギャップ分析

不足しているスキル・経験を次の3段階に分類する

- 致命的 (必須要件の中核、代替が効かない)
- 重大 (必須要件だが周辺技術で代替できる可能性がある)
- 軽微 (歓迎要件レベル、学習意欲でカバー可能)

各ギャップについて、職務経歴書や自己PRでどう補うか、面接でどう説明するかの方針を添える

### ステップ4 レッドフラグの検出

求人票の記述から、業務量・企業文化・報酬面で懸念がある表現を洗い出す。次を判断基準の例とする

- 業務量 「裁量労働」「スピード感」「ワンチームで何でもやる」といった語の過度な強調、みなし残業時間が長い
- 企業文化 「アットホーム」「体育会系」など主観的な社風表現のみで具体性がない
- 報酬面 給与レンジの幅が極端に広い、賞与や昇給の記載がない
- 募集要項 同じポジションの募集が長期間・頻繁に出ている (定着率への懸念)

判断材料として提示するにとどめ、応募の可否は本人の判断に委ねる

## 職務経歴書の調整手順

事実を曲げず、経験の中から関連性の高い部分を選んで強調するのが原則
未経験の技術を経験したかのように書かない

1. **開発経歴の掲載順を関連度順に変更** 求人と関連が深いプロジェクトを上位に配置する
2. **実績箇条書きの並び替え** 各プロジェクト内で、求人に最も関連する実績を先頭に記載する
3. **表現の調整** 求人票で使われている用語 (製品名、技術名、役割名) を、実態に即した範囲で自然に取り込む

## 出力形式

分析結果は次の形式でまとめる

```
## 求人 (会社名・職種)

### マッチ度: XX%

### 強み
- (該当する必須/歓迎要件と、対応する自分の経験)

### ギャップ
- 致命的: ...
- 重大: ...
- 軽微: ...

### 職務経歴書の調整方針
- (開発経歴の並び順、強調する実績)

### エージェント・面接での補足ポイント
- (ギャップの説明の仕方、レッドフラグへの確認事項)
```

## 作業の進め方

1. 求人票の全文を受け取る
2. 現在の職務経歴書 (jp-resume-writerで作成したもの) と突き合わせる
3. マッチ度とギャップを算出し、出力形式でまとめる
4. 職務経歴書の調整が必要な場合、具体的な並び替え案を提示する
5. 以下をもとに`AskUserQuestion`ツールを呼び出してユーザに確認する

   ```
   questions:
     - question: 提示した並び替え案で職務経歴書ファイルを修正しますか
       header: 修正の承認
       multiSelect: false
       options:
         - label: 承認
           description: 提示した並び替え案のとおりに職務経歴書ファイルを修正する
         - label: 修正しない
           description: 分析結果の提示のみで終了する
   ```

   承認が得られた場合のみ、実際に職務経歴書ファイルを修正する

## このskillで扱わないもの

- ゼロからの職務経歴書作成・添削、実績の書き方や数値化 (jp-resume-writer を使う)
- 個人開発プロジェクトの詳細なケーススタディ作成 (jp-portfolio-case-study を使う)
